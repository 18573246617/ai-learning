### 1.2 为什么文件/内存存储到头了

第 1–6 周的 `repositories` 用内存数组、JSON 文件存数据，它们和 PostgreSQL 的本质区别：

| 能力 | 内存/文件 | PostgreSQL |
|---|---|---|
| 重启后数据 | 内存丢、文件脏 | 持久化，服务重启/崩溃数据都在 |
| 多人同时写 | 一个进程里互相覆盖 | 并发控制，多请求安全 |
| 查询 | 自己写 filter/sort 逻辑 | `WHERE / ORDER BY / LIMIT` 一条 SQL |
| 数据完整性 | 靠代码自觉 | 约束兜底（类型、唯一、外键） |
| 数据量 | 撑到几百条还行 | 百万条也扛得住 |

你在第 2 周手写的"查任务数组再 filter"的逻辑，以后就变成数据库做的事。`repositories` 那层依然存在，只是里面从"操作数组"变成"执行 SQL"。

### 1.3 SQL 四大类（本周学三类）

| 类别 | 全称 | 本周任务 |
|---|---|---|
| DDL | 定义结构 | `CREATE TABLE` 建表（练习 2） |
| DML | 操作数据 | `INSERT / UPDATE / DELETE`（练习 3、4） |
| DQL | 查询数据 | `SELECT` 过滤、排序、分页（练习 5） |
| DCL | 权限管理 | 不做，面试能提"权限走 GRANT / 角色"即可 |

## 3. 三分钟概念地图：SQL 世界 = 你熟悉的 TS 世界

你在第 1 周就写过这种 TS 类型：

```ts
interface User {
    id: number
    username: string
    passwordHash: string
    createdAt: Date
}
```

SQL 里的对应物：

| SQL 概念 | 类比 | 说明 |
|---|---|---|
| database | 一个独立项目 | 一个库给一个应用用，别全塞一起 |
| table（表） | `User[]` 数组 | 一张表存一类对象 |
| row（行） | 数组里的一个对象 | 一条记录 |
| column（列） | 对象的字段 | 列的类型 = TS 类型 |
| constraint（约束） | TS 类型检查 | 数据库替你拦非法数据 |

常用列类型（先记这 6 个就够）：

| SQL 类型 | 类比 TS | 用在哪 |
|---|---|---|
| `BIGINT` | `number`（整数） | `id`、计数 |
| `TEXT` / `VARCHAR(n)` | `string` | 长文本用 TEXT；定长/限长用 VARCHAR(n) |
| `BOOLEAN` | `boolean` | `completed` |
| `TIMESTAMPTZ` | `Date` | `created_at`——**永远用带时区的 timestamptz** |
| `NUMERIC` | number（要精确） | 金额，别用浮点 |
| `JSONB` | `object` | 第 11 周存聊天记录用 |

> 一句话：**表 = 类型 + 数组，行 = 对象，SQL = 对数组做 filter/sort/paginate 的语法**。你已经有 80% 的心智模型了。

## 5. 建表 = 给数据的"类型检查"（练习 2，本周核心 60 分钟）

### 5.1 CREATE TABLE 语法骨架

```sql
CREATE TABLE 表名 (
    列名 类型 约束,
    列名 类型 约束,
    ...
);
```

### 5.2 五类约束（背下来，面试/排错都靠它）

| 约束 | 作用 | 违反时报什么 |
|---|---|---|
| `PRIMARY KEY` | 主键：唯一 + 非空，一条记录的身份证 | 重复 id 报错 |
| `NOT NULL` | 不允许为空 | `null value in column ... violates not-null` |
| `UNIQUE` | 值不能重复（**但多个 NULL 允许**，后面练） | `duplicate key value ... violates unique`，SQLSTATE `23505` |
| `DEFAULT` | 不填时用默认值 | 不会报错，自动填 |
| `FOREIGN KEY` | 外键：引用另一张表的某列，防止"孤儿数据" | `violates foreign key constraint`，SQLSTATE `23503` |

还有 `CHECK`（值范围检查）本周顺带认识即可，第 8 周加索引时一起深入。

### 5.3 生产级命名规范（从这周开始养成）

- 表名：复数、全小写、下划线分隔（`users`、`tasks`、`task_tags`）
- 列名：全小写蛇形（`password_hash`，不是 `passwordHash`）
- 主键统一叫 `id`
- 时间列统一 `created_at` / `updated_at`，类型一律 `TIMESTAMPTZ`
- 外键列 = 被引用表名单数 + `_id`：`tasks.user_id` 引用 `users.id`

> 为什么坚持这套约定？因为以后 Prisma model 直接映射表，命名混乱会让 schema 没法看；而且第 6 周学的"一致性"原则在这里同样适用。

### 5.4 第 6 周的 users 表，SQL 版

你 week2 的注册登录用户，在数据库里长这样：

```sql
CREATE TABLE IF NOT EXISTS users (
    id            BIGINT        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username      VARCHAR(50)   NOT NULL UNIQUE,
    email         VARCHAR(255)  UNIQUE,
    password_hash TEXT          NOT NULL,
    created_at    TIMESTAMPTZ   NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ   NOT NULL DEFAULT now()
);
```

注意三件事：

1. **`BIGINT GENERATED ALWAYS AS IDENTITY`** 是标准写法：主键自动生成、不回退，比老语法 `SERIAL` 更现代（PG 10+ 用 IDENTITY）
2. `email` 允许 NULL，但 UNIQUE——PostgreSQL 允许**多个 NULL**，所以"三个用户都没填邮箱"不冲突，这正符合真实业务
3. `created_at` 用 `DEFAULT now()`：插入时不填自动打时间戳，类型是带时区的 `TIMESTAMPTZ`

再建第 6 周待办对应的表（第 8 周才正式学 JOIN，这里先把外键立起来）：

```sql
CREATE TABLE IF NOT EXISTS tasks (
    id         BIGINT        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id    BIGINT        NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title      TEXT          NOT NULL,
    completed  BOOLEAN       NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ   NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ   NOT NULL DEFAULT now()
);
```

`REFERENCES users(id) ON DELETE CASCADE` 翻译成人话：**任务必须属于一个真实存在的用户；用户被删时，他的任务一起删**。没有外键的话，用户删了任务还挂着，就是"孤儿数据"。

## 8. SELECT：查询、排序、分页（练习 5，60 分钟）

### 8.1 SELECT 的结构 = 挑列 + 过滤行 + 排序 + 限量

```sql
SELECT 列1, 列2            -- 要哪几列（别没事就 *）
FROM 表
WHERE 条件                 -- 要哪些行
ORDER BY 列 ASC|DESC       -- 排序
LIMIT 数量 OFFSET 跳过几行; -- 分页
```

### 8.2 常用条件

| 需求 | 写法 |
|---|---|
| 精确相等 | `WHERE username = 'alice'` |
| 不等于 | `WHERE completed <> TRUE` |
| 开头/包含模糊（忽略大小写） | `WHERE username ILIKE 'a%'` |
| 在集合里 | `WHERE id IN (1, 2, 3)` |
| 区间 | `WHERE created_at BETWEEN '2026-09-01' AND '2026-09-30'` |
| 为空 | `WHERE email IS NULL` |

### 8.3 排序 + 分页（本周重点）

查 alice 未完成的最近任务：

```sql
SELECT id, title, completed, created_at
FROM tasks
WHERE user_id = (SELECT id FROM users WHERE username = 'alice')
  AND completed = FALSE
ORDER BY created_at DESC, id DESC
LIMIT 10 OFFSET 0;
```

分页公式（对应你 week2 接口里的 `page` / `pageSize`）：

```text
OFFSET = (page - 1) * pageSize
第 1 页(page=1, pageSize=10) → LIMIT 10 OFFSET 0
第 2 页(page=2, pageSize=10) → LIMIT 10 OFFSET 10
```

查总数拿总页数：

```sql
SELECT count(*) FROM tasks WHERE user_id = 1;
```

> 提前埋个钩子：`LIMIT/OFFSET` 在数据量大以后会越来越慢（每翻一页都要从头数），第 10 周会学"游标分页"。本周先把 OFFSET 公式用熟。

### 8.4 关于参数化（重要，虽然本周还没写 Node）

以后在 Node 里把 `page` 拼进 SQL 字符串会挨 SQL 注入；正确姿势是占位符参数（pg 用 `$1 $2`，Prisma 直接传 TS 变量）。本周先在脑子里留个印象：**SQL 字符串禁止直接拼接用户输入**。

|---|---|---|

| `02-insert-data.sql` | 插入用户 + 任务（先清空再插，保证幂等） | 能 |
