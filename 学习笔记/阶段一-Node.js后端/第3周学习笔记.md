## 1. fs：文件读写

### 1.1 一次性读：readFile

```ts
import { readFile } from "node:fs/promises"

const content = await readFile("./data.txt", "utf8")
console.log(content)
```

`readFile` 会把**整个文件一次性读进内存**，返回完整内容。适合小文件（配置、笔记）。

### 1.2 流式读：createReadStream

```ts
import { createReadStream } from "node:fs"

const stream = createReadStream("./big.log", "utf8")
let count = 0
stream.on("data", (chunk) => {
  count++
  console.log(`第 ${count} 块：`, chunk.length, "字符")
})
stream.on("end", () => console.log("读完了，共", count, "块"))
```

`createReadStream` 把文件**分成一块一块**流式读取，内存只占一块的量。适合大文件（几百 MB 日志）。

### 1.3 写文件

```ts
import { writeFile, appendFile ,open} from "node:fs/promises"

//如果文件不存在，那么这三个都会创建文件
await writeFile("./out.txt", "Hello")   // 覆盖写
await appendFile("./out.txt", " World") // 追加写


// 'w'	打开即清空，从 0 字节开始写	覆盖写
// 'a'	保留原内容，所有写入自动追加到末尾	追加写
// 'r+'	不清空，从文件开头覆盖写	原地修改
const fd1= await open("./out.txt", "w")
await fd1.appendFile('覆盖的')//此处虽然是追加但是使用了‘w’，为覆盖
await fd1.close()

const fd2=await open("./out.txt", "a")
await fd2.writeFile('追加的')//此处虽然是覆盖但是使用了‘a’，为追加
await fd2.close()


```

## 2. Stream 与背压

### 2.1 流是什么

数据像**水管里的水**一样一段一段流过，而不是整桶倒给你。`readFile` 是"整桶倒"，流是"水管慢慢流"。

### 2.2 pipe：把两个流接起来

```ts
import { createReadStream, createWriteStream } from "node:fs"

createReadStream("./big.log").pipe(createWriteStream("./copy.log"))
```

一行代码完成文件复制。`pipe` 会自动：读一块 → 写一块 → 再读一块。

### 2.3 背压（backpressure）

生产速度 > 消费速度时，如果不控制，内存会爆。`pipe` 内部自动处理背压：消费者处理不过来时，自动暂停读取；处理完了再继续。这是流式处理的"地基"，第 14 周做 AI 流式对话、大文件上传都靠它。

## 3. SSE：服务器向浏览器推送

### 3.1 是什么

SSE（Server-Sent Events）让服务器**单向、持续地**向浏览器推送消息。AI 聊天"打字机效果"、进度通知都靠它。

### 3.2 格式（核心考点）

```
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

data: 你好

data: 我是第二段

```

要点：`Content-Type` 是 `text/event-stream`；每条消息 `data: 内容` 开头；**每条消息以空行（\n\n）结尾**。

- 用 `setInterval` 每秒推一条，客户端断开时 `clearInterval`

## 5. crypto：哈希与随机数

### 5.1 哈希

```ts
import { createHash } from "node:crypto"

const hash = createHash("sha256").update("密码123").digest("hex")
// SHA-256 是一种哈希算法 (SHA-256 = "把任意内容压成 64 位十六进制指纹的机 器"——出厂设定：同进同出、改一全变、不可还原。 )
// SHA-256	256 位（64 字符）	✅ 当前主流	文件校验、证书、区块链
// SHA-512	512 位（128 字符）	✅ 安全	更慢更安全，特殊场景
// bcrypt / pbkdf2	可变	✅ 密码专用	存密码用这个，不是 SHA！

// update('密码')+update('123')  =>update("密码123")用于拼接

// digest(hex)  :相当于把密码123转化为hash值+处理为16进制字符串 （默认是二进制） 
//  (): 二进制 Buffer（32字节 / ('hex'): 十六进制字符串 ← 最常用/('base64'): base64 字符串

console.log(hash) // 64 位十六进制字符串
```

特点：**不可逆**（无法从结果反推原文）、同样输入永远同样输出、长度固定。

### 5.2 随机数

```ts
import { randomBytes } from "node:crypto"

//randomBytes(16)创建16个字节，转成 32 位十六进制字符串
//1字节==2位 hex

const token = randomBytes(16).toString("hex")
console.log(token)
```

- 想一想：为什么密码存储要用"带盐的哈希"而不是直接存哈希？（第 4 周用 bcrypt 揭晓）
  因为直接存哈希时，相同密码 → 相同哈希，攻击者用「彩虹表」（预先算好的常见密码↔哈希对照表）就能直接反查破解。加盐 = 给每个用户拼一段随机字符再哈希，让相同密码也产生不同哈希，彩虹表失效。

## 7. 常见坑

1. 大文件用 `readFile` → 内存暴涨；应该用 `createReadStream`
2. SSE 里调了 `res.end()` → 连接关闭、推送中断（SSE 是长连接，只 write 不 end）
3. SSE 消息忘了 `\n\n` → 浏览器收不到（格式必须是 `data: xxx\n\n`）
4. `EventSource` 只能发 GET、不能带自定义请求头（和 fetch 不同）
5. `.env` 提交到 git → 密钥泄露（你的 `.gitignore` 已经挡住了）
6. 哈希不是加密：加密可逆，哈希不可逆
