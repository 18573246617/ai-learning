## 1. 部署前必做（本地自查，约 15 分钟）

### 1.1 本地构建先跑通

在项目根目录 `D:\AI学习\代码练习\阶段一-Node.js后端` 执行：

```bash
pnpm build:week2
node dist/week2/index.js
```

浏览器访问 `http://localhost:1300/healthz`，返回 `{"status":"ok"}` 就说明生产构建没问题。

> ⚠️ 如果构建报错或启动失败，**先修好再部署**，不要带病上线。

### 1.2 必须修复：CORS 环境变量名 bug

当前 `src/week2/app.ts` 读的是 `process.env.ORIGIN`，但 .env 里定义的是 `CORS_ORIGINS`，而且白名单比较方式有误（URL 对象和字符串比较永远不匹配）。不改的话线上跨域配置会失效。改成：

```ts
// 顶部：读 CORS_ORIGINS，转成字符串数组
const originList = (process.env.CORS_ORIGINS ?? '')
  .split(',')
  .map((s) => s.trim())
  .filter(Boolean)

// cors 配置里：字符串直接比较
app.use(cors({
  origin(origin, cb) {
    if (!origin || originList.includes(origin)) {
      cb(null, true)
    } else {
      cb(new Error('不允许的跨域来源'))
    }
  },
  credentials: true,
}))
```

### 1.3 必须处理：JWT_SECRET 已经进了 git 历史

`env/.env.development` 目前被 git 跟踪（`git ls-files` 能查到），说明你的开发密钥已经提交到了 Gitee 仓库。生产环境**不能复用这个密钥**：

1. 生成一个全新的生产密钥（不要用旧的）：
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
   把输出的 64 位字符串记下来，部署时填到平台的 JWT_SECRET 变量里。
2. 把开发环境变量移出 git 跟踪（文件保留在本地，以后不再提交）：
   ```bash
   git rm --cached "代码练习/阶段一-Node.js后端/env/.env.development"
   git commit -m "chore: 停止跟踪 .env 文件（密钥不入库）"
   ```
3. 项目里补一份 `.env.example`（只写变量名和注释，不写真值），告诉后来的人需要配哪些变量。

### 1.4 已知限制（先知道，不阻塞）

- `uploads/` 目录在 Railway 上是**临时磁盘**：重启/重新部署后上传的文件会丢失。本周部署用于演示和验证，没问题；生产环境要接对象存储（OSS/S3），阶段三会涉及。
- 测试命令 `pnpm test` 建议部署前跑一遍，确认全绿再上线。

## 2. 把代码推到 GitHub

### 2.1 创建 GitHub 仓库

1. 打开 github.com，登录后点 New repository
2. 仓库名填 `ai-learning`（或 `ai-learning-backend`），**公开或私有都行**，不要勾选"初始化 README"（本地已有仓库）
3. 创建后复制仓库地址，形如 `https://github.com/你的用户名/ai-learning.git`

### 2.2 本地添加远程并推送

在 `D:\AI学习` 执行：

```bash
# 先确认当前改动都已提交（git status 干净）
git add -A
git commit -m "feat: 第 5 周部署前收尾"

# 添加 GitHub 远程（保留 Gitee 的 origin，用新名字）
git remote add github https://github.com/你的用户名/ai-learning.git

# 推送（第一次推可能要求登录 GitHub）
git push github master
```

推送成功后，GitHub 上能看到代码即可。

> 💡 更干净的做法（推荐给以后的项目）：把后端代码单独放一个仓库，而不是和学习笔记混在一起。现在是学习阶段，先这样推没问题。

## 3. Railway 部署步骤

### 3.1 注册并连接

1. 打开 railway.app，注册/登录（可以用 GitHub 账号登录，省一步授权）
2. 首次使用按提示授权 GitHub：Railway 需要读取你的仓库列表

### 3.2 创建项目

1. 点 **New Project**
2. 选 **Deploy from GitHub repo**
3. 在仓库列表里选中刚推送的 `ai-learning`
4. Railway 会自动开始第一次部署（大概率会失败，正常，继续下面的配置）

### 3.3 关键配置（在服务 Settings 里）

点击部署出来的服务 → **Settings**：

| 配置项 | 填什么 | 说明 |
|---|---|---|
| **Root Directory** | `代码练习/阶段一-Node.js后端` | 你的 package.json 在这个子目录里，必须指过去（在 Source 区域） |
| **Build Command** | `pnpm install && pnpm build:week2` | 安装依赖 + 编译 TypeScript |
| **Start Command** | `node dist/week2/index.js` | 跑编译产物，不跑 tsx |
| **Healthcheck Path** | `/healthz` | Railway 用它判断服务存活 |

> 如果 Root Directory 填中文路径报错，就把后端代码单独推一个仓库（第 2.2 节备注的做法），Root Directory 留空。

### 3.4 配置环境变量（Variables）

在服务的 **Variables** 区域逐个添加：

| 变量名 | 值 | 说明 |
|---|---|---|
| `JWT_SECRET` | 第 1.3 步生成的新密钥 | 必须填，否则登录/鉴权全挂 |
| `CORS_ORIGINS` | 你的前端域名（还没有就留空） | 留空 = 不限制跨域来源，先跑通再说 |
| `PORT` | 不用填 | Railway 会自动注入，代码直接读 process.env.PORT |

> ⚠️ 绝对不要把 `env/.env.development` 的内容复制过来——那里面有旧的开发密钥。

### 3.5 触发重新部署

配置改完后，点 **Deploy**（或 Settings 里手动 Redeploy），等部署日志跑完，看到类似 `服务已启动` 的日志就是成功了。

### 3.6 生成公网域名

1. 服务页面点 **Settings → Networking**
2. 点 **Generate Domain**
3. 得到一个形如 `https://xxx.up.railway.app` 的地址，记下来

## 6. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 部署失败：找不到 package.json | Root Directory 没配 | 按 3.3 填 `代码练习/阶段一-Node.js后端` |
| 启动失败：Cannot find module './app.js' | 编译目录不对或没跑 build | Build Command 确认是 `pnpm install && pnpm build:week2` |
| 登录接口报 500 | JWT_SECRET 没配 | 去 Variables 补上，重新部署 |
| /healthz 通，但注册/登录失败 | 日志里看具体报错 | 大概率是变量缺失，对照 3.4 |
| 浏览器访问被 CORS 拦截 | CORS_ORIGINS 没包含前端域名 | 把前端地址（协议+域名+端口）填进 CORS_ORIGINS，重新部署 |
| 上传的文件重启后没了 | Railway 磁盘是临时的 | 预期内，本周不管；生产接对象存储 |
| Railway 需要绑卡/试用额度用完 | 平台政策 | 换备选方案 Zeabur，流程基本一致（GitHub 导入 → 配变量 → 生成域名） |
