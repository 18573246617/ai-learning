# AI 应用开发 / Agent 开发 转岗学习计划（36 周）

> 适用对象：在职前端开发者（会 JS/React，Node.js 后端和数据库需要从零补起）
> 学习节奏：周一至周四每晚 1–1.5 小时 + 周六 4 小时 + 周日 4 小时 ≈ 每周 13–15 小时
> 总时长：约 8–9 个月

---

## 一、核心思路

AI 应用开发（Agent 开发）的本质不是训练模型，而是**把大模型的能力集成进真实产品**。需要的能力是：服务端开发、流式数据处理、检索、工具调用编排、对话体验。

- 前端经验是优势，不是负担：交互、流式 UI、状态管理、API 集成直接复用
- 全程使用 **TypeScript**，JS 基础直接迁移，不强制学 Python（会一点是加分项）
- 主学 **Express 5**，数据库只用 **PostgreSQL**，ORM 用 **Prisma**
- 框架会过时，**原理永远保值**：ReAct、工具调用、记忆、RAG 是面试重点

## 四、阶段二：数据库（第 7–12 周）

**选型结论**：只用 PostgreSQL。理由：

1. AI 应用事实标准，RAG 向量检索内置（pgvector 插件）
2. `JSONB` 灵活存聊天记录、Agent 状态等非结构化数据
3. Supabase（免费托管）基于 Postgres，作品集零成本上线

### 第 7 周：PostgreSQL 上手 + SQL 基础

- [ ] Docker 跑 Postgres + pgAdmin
- [ ] `CREATE TABLE`：主键、外键、唯一约束、默认值
- [ ] `INSERT / UPDATE / DELETE`
- [ ] `SELECT`：过滤、排序、分页（`LIMIT/OFFSET`）

**产出**：用 SQL 建 users 表并增删改查

### 第 8 周：关系与索引

- [ ] 一对多、多对多（中间表）、一对一，先画 ER 图再建表
- [ ] `JOIN`：INNER / LEFT，何时用哪个
- [ ] 聚合：`COUNT`、`GROUP BY`、`HAVING`
- [ ] 索引：何时建、`EXPLAIN` 读执行计划（看懂即可）

**产出**：users + tasks + tags 三张关联表，能写多表查询

### 第 9 周：Prisma 接入

- [ ] Prisma schema：model、字段类型、关系、枚举
- [ ] `migrate` 和 `seed` 流程
- [ ] 把注册登录接上 Postgres（替换内存存储）
- [ ] Prisma Client 基础查询：`findUnique`、`create`、`update`

**产出**：用户系统真正持久化，重启数据不丢

### 第 10 周：Prisma 进阶 + 事务

- [ ] 关系查询：`include`、嵌套创建、`where` 条件
- [ ] 分页：`skip/take` 与游标分页区别
- [ ] 事务：`prisma.$transaction`，"全成功或全回滚"
- [ ] 待办任务挂到用户下，实现"我的任务"接口

### 第 11 周：Redis 与 JSONB

- [ ] Redis 概念：缓存、会话、简单队列；`set/get/expire`
- [ ] `ioredis` 给热门接口加缓存（TTL）
- [ ] `JSONB` 存一段聊天记录
- [ ] 连接池概念：为什么不能每请求新建连接

**产出**：带缓存层的 API，能说清缓存失效策略

### 第 12 周：pgvector 向量检索（进入 AI 的桥）

- [ ] 理解 embedding：文字 → 一串数字，语义相近数字相近
- [ ] 用 DeepSeek embedding 接口给文本生成向量
- [ ] `vector` 列写入向量，余弦相似度检索（`<=>` 运算符）
- [ ] 概念了解 HNSW 索引

**产出**：输入一句话，从文本库返回最相关的 3 条

**阶段产出**：用户系统 + 待办 + 缓存 + 向量检索接口的完整后端

## 十、避坑提醒

- 学练比 3:7：别刷完教程再动手，学一个概念就改代码验证
- 别追新框架：原理（ReAct、工具调用、记忆）比任何框架值钱
- 别依赖低代码平台（Coze/扣子）：可以玩，但求职看代码能力
- 不要从 MySQL 起步：直接 PostgreSQL，一步到位
- 评估是隐藏考点：会评测 Agent 输出质量的人很少，提前培养
