## 一、2026 年 11 月的市场事实

### 1. JD 词频：Python 是硬门槛，不是加分项

2026 年 8 月在招岗位的 JD 词频统计（单一样本，但方向明确）：

- **几乎必提**：Python（90%+）、RAG（分块 / embedding / 重排）、Agent（LangChain / LangGraph / Dify / LlamaIndex）、Prompt、Function Calling、**MCP**、Linux / Git / Docker、**FastAPI**、Redis / MySQL / 至少一种向量库、结构化输出、评测意识、AI 编程工具（Cursor / Claude Code）
- **中频**：Go / Java / Node.js（第二后端语言）、vLLM / Ollama、Kafka、K8s、A2A、GraphRAG / LightRAG、Human-in-the-loop、幻觉治理、token 成本优化
- **低频加分**：SFT / RLHF / DPO、多模态、Spring AI、端侧小模型

来源：[AI 应用工程师学习文档（2026 全网最全版）](https://juejin.cn/post/7677780984578293801)（2026-08-25，基于 Boss 直聘 / 猎聘 / 智联 JD 整理）

### 2. 岗位要的是"端到端交付 + 评测闭环"，不是"会调 API"

一条 20–30k 的 JD 原文把职责拆成五块：端到端交付（方案→开发→部署→迭代）、RAG 核心链路（解析 / 分块 / 索引 / 混合检索 / 重排 / 引用溯源）、Agent 核心能力（意图识别 / 编排 / 记忆 / 工具封装 / 兜底 / 人审）、工程化（并发 / 成本 / 监控 / 日志）、**评测与迭代闭环**（评测集、检索命中率、工具调用成功率）。

同一篇的总结很准：**市场要的不是"会调 API 的人"，是"能把 AI 从 Demo 做到稳定生产、并证明效果的人"。**

来源：同上；[国产大模型密集发布催生哪些新岗位](https://www.zpedu.com/it/ai/47996.html)（2026-10-26，提到智能体开发 / 编排 / 运维、AI 部署工程师、FDE 等新岗位）

### 3. 框架和协议已经换代

- **LangGraph 1.0** 已是企业默认的图编排方案（Python / TS 双语言，显式状态图、checkpoint、HITL、LangSmith 可观测）；同场竞争者：OpenAI Agents SDK、Claude Agent SDK、CrewAI、Microsoft Agent Framework、Google ADK、LlamaIndex Workflows、Pydantic AI、**Mastra（TS）**
- **MCP**：2024-11 开源 → 2025-04 ChatGPT 接入 → 2025-12 捐给 Linux Foundation AAIF → **2026-07-28 规范**（无状态核心 / Tasks / MCP Apps / OAuth 对齐）。工具接入已经"基础设施化"
- **A2A**：Agent ↔ Agent 的协议，和 MCP 同基金会，分工是"MCP 接工具，A2A 接同事"
- **Agent Skills**：以 `SKILL.md` 描述可复用能力的封装方式，和 MCP 并列成为扩展手段，JD 里已经出现 "SKILL" 字样

来源：[Agent 框架与协议标准：从原理到搭建](https://bbs.huaweicloud.com/blogs/508973)（2026-10-28）；[MCP 2025-11-25 → 2026-07-28 迁移指南](https://modelcontextprotocol.info/docs/tutorials/migrating-to-2026-07-28/)；[LangChain / LangGraph 1.0](https://www.langchain.com/blog/langchain-langgraph-1dot0)

## 三、两个方案（等你拍板）

### 方案 A：Python 桥接后双栈（推荐）

第 13–14 周补 Python / FastAPI，第 15 周起 LLM / RAG / Agent 全部用 Python 写；前端 ChatUI 继续用 TS + Vercel AI SDK。

- **补什么**：语法对照（类型注解 / Pydantic / async / 生成器）→ FastAPI（路由、依赖注入、Pydantic 模型、`StreamingResponse`、SSE、异常、中间件）→ SQLAlchemy async + asyncpg 对照 Prisma → uv / ruff / pytest 工具链
- **怎么补**：拿已经写过的待办 API 用 Python 重写 2 个接口 + 1 个 SSE 流，不学新业务，只换语言
- **优点**：对齐 90% JD；Ragas / Langfuse / LangGraph / FastMCP 的生态都在 Python 侧；已有后端知识（HTTP / 分层 / SQL / 事务）100% 迁移
- **代价**：多 2 周；要接受"两种语言都写"的日常
- **适合**：目标社招 AI 应用 / Agent 岗

### 方案 B：保持 TypeScript 单栈

LangGraph.js + Mastra + AI SDK，不碰 Python。

- **优点**：不换语言，出活最快；前端优势最大化
- **代价**：岗位面窄（TS Agent 岗集中在外企、初创、前端团队）；Ragas / Langfuse / 多数 MCP 示例要绕；JD 里"Python 90%+"这一关过不了
- **适合**：目标"AI 产品前端 / AI 全栈"，或现公司内部转岗
